# Fun-First UI Direction

## Main experience

The default experience should resemble a six-lane race broadcast more than a spreadsheet with animated dots.

Each method still runs simultaneously, but the interface should emphasize:

- current leader and changing rank
- progress toward final seating
- visible bottlenecks
- notable events
- short explanatory callouts
- character moments
- a satisfying finish and post-race recap

## Suggested viewing modes

### Race overview

All six cabins remain visible. Cards show current place, estimated momentum, seated count, and a small event ticker.

### Head-to-head

Two selected methods are enlarged and synchronized. Differences in queue and conflict behavior are easier to see.

### Story mode

One method fills most of the screen. Character labels, speech bubbles, event animations, and an event log are enabled.

### Replay mode

The user can pause, step, scrub, jump to notable events, and compare the same moment across methods.

## Visual vocabulary

- Bag icon: stowing or struggling with luggage
- Seat arrows: passengers moving aside during a conflict
- Footprints or motion trail: walking
- Pause symbol: waiting behind a blocker
- Party bracket or connector: people traveling together
- Speech bubble: short human-readable event explanation
- Lightning or alert badge: disruptive event
- Spotlight ring: selected passenger or current bottleneck

Color must not be the only indicator. Icons, outlines, labels, and patterns should carry the same information for accessibility.

## Event presentation

An event should have three layers:

1. **Quick animation** — immediately visible in the cabin
2. **Ticker message** — for example, "Barbara has joined the queue late"
3. **Inspector detail** — exact mechanical effect and added delay

The comedy should never hide the mechanics. A user should be able to tell whether the event inserted a passenger, changed queue order, added bag time, reversed movement, or blocked the aisle.

## Post-race presentation

The finish should show:

- podium or ranked finish order
- time gaps
- "turning point" events
- largest source of delay for each method
- best and worst passenger experience
- how much chaos changed the result
- replay buttons for decisive moments

## Controls

Long technical control panels should be secondary. The default screen should lead with scenario cards such as:

- Smooth business flight
- Family vacation
- Holiday crush
- Perfect laboratory
- Barbara mode
- Build your own

Advanced controls remain available in a drawer.
